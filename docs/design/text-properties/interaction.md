# Рабочее пространство Composa для макета и ретуши

[Открыть кликабельный макет](workspace.html) · [Посмотреть кадр примерки](workspace.png)

## Решение для проверки

Одна рабочая область. Выбор на холсте определяет, что можно изменить. Инструмент определяет смысл следующего жеста. Эти два состояния видны одновременно. Например, «Кисть» сообщает, **чем** рисуем, а «Волна / Маска» — **куда** попадёт мазок. Ретушь часто требует долго удерживать одну цель. Верстка требует быстро менять цель между соседними объектами. Автовыбор в процессе рисования смешал бы эти намерения.

В действующем редакторе уже есть выбор слоя через видимые пиксели, Shift для добавления объектов, привязки, выравнивание к холсту и второму объекту, а также независимые цели для пикселей и маски. Однако часть операций с уже выбранным объектом открывается при смене инструмента. Это видно в [панели параметров](../../../src/Composa.App/MainWindow.Options.cs), [описании перемещения](../../tools.md) и [описании слоёв](../../layers.md). Первый выигрыш стоит искать в устранении этих переключений.

## Как ведёт себя редактор

| Намерение | Жест и результат |
| --- | --- |
| Поменять оформление заголовка | В режиме выбора клик выбирает надпись, инспектор сразу показывает её типографику. Двойной клик входит в набор. При выделенном фрагменте инспектор называет область применения и изменение затрагивает этот фрагмент. |
| Примерить несколько семейств | Одно открытие списка. Наведение или стрелки обновляют строку в композиции, сохраняя её размер и привязку рамки. Клик или Enter подтверждает. Первый Escape закрывает список и восстанавливает оформление. При многострочном тексте переносы должны быть видны в рамке во время примерки. |
| Собрать несколько объектов | Shift добавляет объект на холсте или в дереве. Для выбора двух слоёв первыми показываются выравнивание и имя опорного объекта. Для трёх — также распределение промежутков. Для нескольких текстов можно далее согласовать общие свойства и явную индикацию смешанных значений. |
| Разобраться в сложной композиции | Кнопка «Объекты» открывает дерево. В полном редакторе предложены закрепление, видимость и блокировка, поиск, миниатюры масок и раскрытие группы до выбранного объекта. При перекрытии — команда выбора объекта под указателем со списком имён. При частой работе с масками дерево можно постоянно держать раскрытым. |
| Перейти к обработке растра | Когда активен подходящий растровый слой или его маска, кисть сразу готова рисовать по нему. Если выбран текст, программа предлагает явный выбор цели. Выбор другого объекта не должен происходить от первого мазка. В учебном документе единственная доступная цель — маска волны. |
| Продолжить компоновку | Возврат к выбору восстанавливает предыдущее выделение, если объекты по-прежнему существуют. Изменения маски сохраняются. Центр и масштаб документа остаются на месте. |

**Размещение.** Постоянная полоса инструментов у края рабочей области, инспектор в фиксированной колонке, дерево открывается по запросу и может быть закреплено. При пустом выборе инспектор показывает документ, при выборе слоя — его свойства, при выборе кисти — цель мазка и настройки кисти. Начальное состояние для новичка — видимые названия основных действий. Поиск команд и горячие клавиши остаются параллельными путями. Для маленького экрана первыми сворачиваются вспомогательные панели. Режим «только холст» и имеющиеся рабочие пространства следует сохранить.

**Что показал бы другой выбор.** Постоянные две колонки полезны, если приходится ходить по группам и маскам почти после каждого действия. У одной правой колонки со слоями под свойствами есть обратная сторона — список и типографика конкурируют за высоту. Раздельные режимы «Дизайн» и «Ретушь» оправданы для длинной однородной работы, но для одной афиши добавляют переход при каждой правке изображения. В первой версии лучше дать человеку закрепить дерево и сохранить рабочее пространство.

## Граница прототипа

HTML воспроизводит выбор объекта, временный шрифт на всём заголовке, трекинг, Shift-выбор двух надписей, выравнивание по второй, выбор маски, размер кисти, мягкий мазок и отмену. Демонстрационная графика имитирует растровую цель через SVG-маску. Это проверка последовательности действий. Метрики задержки, точность растрирования, горячие клавиши редактора, многострочный набор, полный набор инструментов и свойства из пяти референсов проверяются в нативной реализации. Внешний пунктир и сплошной контур показаны для одной мягкой кисти.

## Как принять решение

В текущей сборке и прототипе дать одинаковое задание с эквивалентной афишей. По возможности пригласить человека, знакомого с Composa, и человека, который впервые её открывает. Между участниками поменять порядок версий, чтобы знание задания меньше влияло на сравнение. Простой пробный прогон выявит явные препятствия, но не даст надёжной оценки предпочтений всех пользователей.

1. «Сравните три шрифта в заголовке и оставьте исходный. Затем выберите другой». Наблюдать, увидел ли человек примерку на холсте, сохранился ли исходный шрифт после отмены, сколько раз открывался список.
2. «Поставьте левый край заголовка по началу подзаголовка. Подзаголовок должен остаться на месте». Проверить результат и спросить до применения, какой объект сдвинется.
3. «Смягчите край волны, сохранив текст редактируемым. Вернитесь к работе с надписями». До мазка спросить, куда он попадёт. Проверить цель, сохранность текста и возврат к выбору.

Для каждого задания записать время, лишние смены инструмента, обращения к дереву, запросы подсказки и ошибочную цель. Отдельно повторить на невысоком экране и с большим деревом слоёв в нативном прототипе. Основания двигаться дальше — оформление доступно прямо после выбора, сравнение шрифтов проходит за одно открытие списка, пользователь правильно предсказывает опорный объект и цель мазка. Если люди регулярно открывают дерево только для проверки цели, следует усилить обратную связь или закрепить дерево по умолчанию.

Первый этап разработки после согласования — сквозной нативный сценарий «выбрать текст → примерить → подтвердить или отменить», сохранив текущие форматы и историю. Затем можно проверить расположение остальной типографики и курсор на настоящих документах. Контейнеры с правилами компоновки и многократное использование стилей требуют отдельной постановки.
