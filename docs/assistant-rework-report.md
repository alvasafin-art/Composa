# Переработка встроенного агента — 12 октября 2026

## Причины сбоев и изменения

| Проблема | Исправление |
| --- | --- |
| Стандартный llama.cpp не загружал новую квантизацию PQ2_0 | Проверен PrismML runtime, запуск с полной папкой библиотек, выбор GGUF и диагностика загрузки. |
| Агент повторно читал состояние вместо продолжения задачи | Результат инструмента теперь остаётся последним сообщением; состояние хоста помещается перед обменом инструментами. Добавлена защита от повторяющихся чтений. |
| Поиск не находил нужный инструмент по формулировке задачи | Улучшен поиск операций, точные имена имеют приоритет, операции выделения находятся по запросам о масках. |
| Открытие документа теряло ход задачи и могло создавать повторные вкладки | Переносятся цель, проверки и журнал. Повторное открытие текущего файла не создаёт вкладку. После выбора документа инструменты повторного выбора скрываются. |
| Модель могла объявить задачу завершённой без проверки | Завершение проходит проверку фактического документа. Ошибки и незавершённые правки откатываются; успешная задача отменяется одним Undo. |
| Генерация скрипта смешивалась с редактированием | Отдельный режим подготовки артефакта с инструментами чтения; Photoshop JSX сохраняется и копируется, но не исполняется в Composa. |
| Модель выдумывала конструктор `TextItem` в JSX | Контекст дополнен точным примером Photoshop DOM. Статическая проверка разбирает JS/ES3 и обнаруживает недопустимые конструкторы; до двух попыток исправления без исполнения кода. Проверки не подменяют настоящий Photoshop. |
| Созданный скрипт мог пропустить объявление `doc` | Runtime предоставляет документированный `doc` как короткий доступ к `app.activeDocument`. Четыре теста проверяют обычный/асинхронный запуск с явным объявлением и без него, включая Undo. |
| Не было доступа к данным задания на диске | Разрешённые пользователем папки, постраничное чтение и список файлов, открытие изображений/проектов, импорт изображений в скриптах. Общие правила доступа для чата, MCP и JS. |
| Запуск сервера был хрупким при загрузке, занятом порте и переносе | Ожидание загрузки, проверка имени модели и размера контекста, сериализация запуска, ожидание остановки своего процесса, однократный повтор запроса генерации при обрыве соединения. |
| Непонятно, работает ли агент | Журнал текущих действий, прошедшее время, остановка, проверка модели с вызовом инструмента, выбор режима и папок в настройках. |

Новые MCP-инструменты: `list_read_folders`, `list_files`, `read_file`, `get_script_api`, `execute_script`. Они проверены через настоящий stdio bridge. Изменения по-прежнему проходят через `EditorSession` и поток интерфейса; отдельного редактора внутри агента нет.

## Проверки

Полная обычная проверка после всех изменений: **481 Core + 584 App = 1065**, ошибок нет; **8** тестов с локальной моделью отмечены пропущенными при отсутствии переменных окружения. Включены три проверки Photoshop DOM-фикстуры для числового размера и `UnitValue`, четыре проверки короткого доступа к документу и десять проверок статической валидации/исправления артефактов.

Отдельные прогоны с настоящим `Ternary-Bonsai-2-27B-PQ2_0.gguf`, PrismML `prism-b10754-2459f68`, Windows и Intel Arc B580:

| Сценарий | Reasoning | Результат | Время |
| --- | --- | --- | --- |
| Редактируемая фигура с точными координатами и цветом | none | Пройден | 141 с |
| Четыре настоящие направляющие без новых слоёв | none | Пройден | 54 с |
| Изменение текста внутри группы с сохранением остальных объектов | none | Пройден | 64 с |
| Выделение → маска → снятие выделения, с проверкой пикселей маски | none | Пройден | 160 с |
| Два слоя в смарт-объект с редактируемым содержимым | none | Пройден | 116 с |
| Каждый второй квадрат сверху, с исключением прямоугольника | medium | Пройден | 376 с |

Это результаты отдельных прогонов, а не один непрерывный запуск всех задач. У каждого редакторского сценария проверены Undo/Redo и реальные объекты документа. У пакетного задания уточнена исходная двусмысленная фраза: первый верхний квадрат перекрасить, второй пропустить; проверки результата не ослаблялись.

Составной сценарий «разрешённая папка → открыть PNG → прочитать JSON → создать все слои → подготовить и исполнить повторно используемый Composa JS → подготовить Photoshop JSX»: **пройден целиком**, reasoning `medium`, **6 минут 49 секунд**. JSX создал текстовый слой через существующий `layer.textItem`, с верными текстом, именем и размером. Итоговый прогон завершился без ошибок.

Первый полный прогон этого сценария дошёл до последней проверки размера шрифта. В тестовой имитации Photoshop был неверный конструктор `UnitValue`: возврат числа из вызова с `new` даёт объект, а не число. Исправлена именно фикстура; проверяется размер в пунктах, количество слоёв, текст, имя и тип слоя. Тип `TextItem.size` описан в [Adobe Photoshop JavaScript Scripting Reference](https://community.adobe.com/havfw69955/attachments/havfw69955/photoshop/676396/3/photoshop-javascript-ref-2020-online2pdf-version.pdf). Следующий прогон обнаружил пропущенное объявление `doc` в созданном Composa-скрипте; это устранено поддержкой короткого доступа в runtime. Проверки JSON-разметки дополнены обеими координатами, обеими сторонами квадратов и сохранением фона, включая выполнение выданного скрипта на отдельном документе.

Самодостаточная сборка `dist/agent-win-x64/composa.exe` собрана; отдельно проверены MCP initialize и завершение при закрытии stdin без SDK. В папку включены инструкция и лицензионные уведомления. Headless-снимки настроек и режимов сохранены в `artifacts/screenshots`.

## Настройки и границы проверки

Рабочий профиль: контекст 16384, ответ 4096, reasoning `medium`, температура 0.15, GPU layers −1. `none` быстрее, но в раннем составном сценарии пропускал часть данных. Даже исправленная интеграция не гарантирует безошибочность каждого ответа модели; сложные задачи на этой машине занимают минуты.

Созданный Composa JS исполняется настоящим встроенным runtime на отдельном документе. JSX проверяется на ограниченной имитации Photoshop DOM: установленного Photoshop здесь нет, запуск внутри него не подтверждён. Linux/macOS в этой сессии не запускались; переносимые пути и команды покрыты тестами, каждой ОС нужен подходящий runtime. Модель и llama-библиотеки не включены в сборку приложения.

Доступ к файлам ограничен явно выбранными папками, только чтением; ссылки/junction не обходят ограничения. PSD и RAW требуют обычного диалога открытия. Vision требует отдельного совместимого mmproj и по умолчанию выключен.
