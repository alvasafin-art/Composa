# AI correctness checks

## FLUX masked edits: preview.15 investigation

The masked execution code was identical in previews .12, .13 and .14. Preview .15 addresses defects present in the earlier path; the local-selection release did not change it.

- **Resolution:** an 80×80 selected region requesting 512×512 was previously inside a 144×144 context resized to 512×512, so the selected area received only about 284×284 model pixels. MP now determines the selected-area scale. Surrounding context uses that same scale, adding pixels instead of taking away the requested resolution. The dialog displays the actual context request. Explicit Expand minimum-side sizes still describe its context crop. Original preserves source pixels.
- **Image/mask registration:** image and mask share one integer content size and right/bottom padding, rather than rounding their aspect to the latent grid. Padding never enters the returned source rectangle. Real stock ComfyUI crop/scale/pad/blur nodes were exercised on odd-size and edge crops, with exact Original pixel preservation and at most two channel levels of resampling error on coordinate ramps.
- **Denoising:** a soft noise mask repeatedly mixes source/noisy latents during the four steps. Controlled live comparisons showed that fully denoising a binary support/halo reduced this contribution. The mask is derived from positive source selection support before blur, pooled onto the 16×16 VAE grid and binarized there, so thin edges, faint selections and partially padded cells receive a fully finished latent. Conditioning remains soft; only the independent source-space layer mask performs the final feather.
- **Blur:** blur formerly ran after resizing with an unscaled pixel radius. It now runs before resizing. Multiple Gaussian passes cover wide values without exceeding the stock node's kernel/sigma ceilings. The context bounds also include its halo.
- **Removal seam:** a real List/Batch test reproduced changed gray background beyond the requested grow/blend zone (200 became 199 at x=50, y=90). The Gaussian output-mask tails were the cause. A finite inward feather on outward support keeps the replacement core opaque and leaves distant background byte-for-byte unchanged.
- **Color matching:** surrounding samples previously included original pixels outside the generated ROI and partially edited feather pixels. This diluted or contaminated the offset; applying mask alpha during correction and again during composition weakened the edge twice. A single average also fails when tone errors differ across the patch. The correction now extends a coarse harmonic tone field from unchanged support within the actual generated ROI. It applies a local tone correction once and distinguishes half-strength subtle from full-strength strong. A spatial-bias regression checks opposing edge errors; texture-amplitude and flat-field checks prevent copying grain or amplifying contrast. Off remains off.

Opt-in tests in `FluxLiveDiagnosticsTests` record decoded results, masks, graphs and metrics. `COMPOSA_FLUX_DIAGNOSTIC_URL` enables VAE/geometry runs; `COMPOSA_FLUX_DIAGNOSTIC_OUTPUT` selects the artifact directory. `COMPOSA_FLUX_PHOTO_URL`, `COMPOSA_FLUX_PHOTO_INPUT` and `COMPOSA_FLUX_PHOTO_OUTPUT` enable photograph tests (the input folder contains the official ComfyUI example files renamed `car-interior.jpeg` and `portrait.jpeg`). `COMPOSA_FLUX_PHOTO_VAE=small|full` runs one decoder group independently. `COMPOSA_MASKED_EDIT_GPU_URL` enables real removal in MP/List and Original/three-image Batch. Ordinary CI does not require a model server and does not make paid requests.

Both installed FLUX.2 VAE choices were compared. Neither is silently replaced. A VAE roundtrip can shift tone even without sampling; model-generated texture, invented objects and decoder approximation cannot be ruled out for arbitrary prompts. The comparisons do not justify resetting the user's decoder or changing every sampler setting. The official [ComfyUI Klein guide](https://docs.comfy.org/tutorials/flux/flux-2-klein) documents the distinction between four-step distilled and base models. The complete six-task photograph series passed continuously with CPU text encoding and tiled VAE, including decoder switches, masks and undo/redo. A stronger exposure-bias regression allows up to 64 channel levels of correction when the decoded ROI is known, retaining the legacy 32-level bound for unidentified results.

Repeated runs crashed the installed Intel PyTorch/XPU backend while `model_patcher`/quantized kitchen tensors moved model weights between CPU and GPU, both when changing a decoder and when reloading the VAE with the same decoder. Independent decoder-group runs after restarting the same approved launcher completed. Tiled VAE alone still crashed when moving text-encoder weights after three completed tasks. Advanced now exposes Auto / Lower VRAM / Standard: Lower VRAM keeps the text encoder on CPU and uses stock tiled VAE nodes (512 px, 64 px overlap); Auto chooses this path on Intel XPU. CPU text encoding took several minutes on this installation, so Standard remains available for ordinary server placement and faster supported configurations. Klein's source latent is reused instead of redundant inpainting encodes. No files in the external ComfyUI installation are modified or deleted; a server disconnect must preserve the editor document. This workaround does not claim to repair arbitrary PyTorch/custom-node backend failures.

## Causes addressed

- **Double compositing:** InpaintStitchImproved already applies a soft blend. Applying the soft editor selection again weakens the patch edge and changes its brightness. Composited outputs now use changed-pixel coverage, retaining the baked transition. The user's selection itself is not modified.
- **Black context at the removal seam:** Stitching against a blackened input can mix black into the reconstructed background. The separate removal graph conditions the model with a black crop but stitches against the original source. Client preprocessing no longer grows/feathers the mask before the workflow repeats those passes.
- **Hidden mask enlargement:** editor feather, preprocessing dilation/feather and workflow grow/blend are different operations. Generative Fill's final coverage stays within the selection; its conditioning grow may provide repair context without enlarging the layer mask. GPT still ignores Fill grow.
- **Resizing and placement:** stitched masked results must have the original canvas size. Incorrectly cropped/rounded outputs are refused instead of being stretched over the selection. A real 79×61 crop/stitch test verifies odd dimensions. Selection upscale sends surrounding context, then crops back to the exact target rectangle; no canvas expansion or selection shift occurs.
- **Alpha/color representation:** Comfy IMAGE inputs can lose alpha. Transparent black and unchanged straight colors are not treated as opaque background edits outside the selected area. Local raw-removal finishing converts premultiplied channels to straight color and back, preserving alpha; it is not applied to already-stitched outputs.
- **Unrelated upscaler dependencies:** execution previously checked all nodes/assets of the pack. It now validates the particular bound graph and the actual selected model filename. Both DAT (UltraSharpV2) and RRDBNet (NMKD-Siax) were exercised on Intel XPU with no diffusion/segmentation nodes, including a 57×43 source.

## What still depends on the model

GPT's mask is prompt-based guidance, not guaranteed hard geometry ([official image guide](https://developers.openai.com/api/docs/guides/image-generation)). GPT receives a rectangular image crop with independent **GPT context padding** and genuine references. Ordinary Fill keeps its original source; Remove/Expand retain black repair areas. The result is fitted to saved crop coordinates and constrained by the soft selection once. Paid-model visual quality needs a funded account. FLUX uses the independent source-space coverage and latent-space denoising described above. Models can still alter framing, invent objects or reconstruct structures differently within the editable area; successful execution alone does not prove visual quality.

Expand now uses a narrow generated overlap into existing pixels and one inward fade across that overlap, filling requested transparent pixels completely. The overlap is capped relative to the image size (and at 64 pixels), so a small canvas does not become a full-image regeneration accidentally. Selection Expand uses the ordinary masked-fill workflow with a black target and the fixed expansion instruction; crop expansion retains its distinct canvas placement and optional whole-image mode.

Correct masking and compositing cannot guarantee identical texture, grain, sharpness, perspective or reconstructed content. FLUX image editing may redraw the conditioning crop, and too little scene context or a very large edit can remain visible even with a mathematically correct blend. Do not globally recolor a stitched patch based on its surrounding pixels: those pixels already came from the original, so that statistic can falsely suggest a correction or alter a legitimate new object.

For a remaining seam, retain the original document, the selection and operation/settings, and compare the downloaded Comfy result with the rendered inserted layer. If they differ, inspect placement/mask/alpha. If both show the same seam, inspect conditioning, mask context, generated texture and the workflow's stitch blend. Increasing feather alone is not a universal repair. Selection feather remains part of the user's selection; Mask Grow/Blend/Context are inference controls, not a second independent selection.

A live FLUX.2 Klein removal test also exposed a semantic failure: an incomplete ellipse left recognizable subject fragments, and the model returned a ghost silhouette. A complete enclosing selection plus the explicit empty-background instruction removed the object in the follow-up test at about 1 MP. Include the whole unwanted subject and its edges; do not interpret successful server execution as proof of correct visual removal. Differences in generated branch detail/color remained model-dependent, so the resulting photo was inspected separately from the geometry tests.

## Agent checks

The chat uses native editor tools plus constrained JavaScript, not textual promises. Real local Qwen tests cover a new blue shape, existing grouped text/color/size/movement, layer-mask creation and one-step Undo. Deterministic tests additionally exercise schema discovery, groups/canvas resizing, repair after a partially failed command, duplicate-name/full-id addressing, tab isolation, and completion without changes. Logs are exposed through Operations, including failures. This does not imply that a language model will correctly interpret every ambiguous or arbitrarily complex request; bounded failure rolls back rather than pretending success.
