# Встроенный агент: запуск и проверка

Откройте Assistant → ⚙. Для локальной модели укажите GGUF и папку llama.cpp с её библиотеками. Можно оставить путь к серверу пустым, если `llama-server` доступен в PATH. Включите автоматический запуск. Кнопка **Test model and tools** проверяет загрузку и настоящий вызов инструмента; одного ответа `/health` недостаточно. Диагностика сохраняет последние строки сервера.

## Ternary Bonsai 2 27B PQ2_0

Для `Ternary-Bonsai-2-27B-PQ2_0.gguf` нужна [сборка PrismML](https://github.com/PrismML-Eng/llama.cpp/releases), включая библиотеки выбранного backend. Обычная llama.cpp не поддерживает этот формат. Не переносите один exe отдельно от DLL. На другой ОС скачайте соответствующий runtime; файл модели можно использовать тот же.

Начальный профиль: Context **16384**, Maximum reply **4096**, Reasoning **medium**, Temperature **0.15**, GPU layers **−1**. В наших прогонах `medium` справился с составной пакетной задачей; `none` быстрее, но хуже удерживал все части задания. Для длинных скриптов можно увеличить ответ до **8192–16384** и контекст до **32768–65536**, если хватает памяти. Большой контекст расходует VRAM. **0** GPU layers означает CPU. `xhigh` заметно увеличивает время ответа. Значение `high` для этой модели не используется.

Ограничения и рекомендации разработчика: [известные проблемы Bonsai](https://huggingface.co/prism-ml/Ternary-Bonsai-2-27B-gguf/blob/main/KNOWN_ISSUES.md). Качество зависит от модели; изменение настроек проверяйте на сценариях ниже. Для vision нужен соответствующий **mmproj** в поле Vision projector; без него оставьте отправку изображений выключенной. Без vision агент проверяет структуру и может использовать инструменты чтения цвета/контуров.

При ручном запуске сервера оставьте `--reasoning auto` и включите `--jinja`; приложение передаёт выбранный режим в запросе. Для одного агента используйте `--parallel 1`. Если старый сервер уже занял порт, остановите его самостоятельно или укажите другой порт: приложение управляет только собственным процессом.

## Vision: агент видит изображение

Поддержка уже встроена: агент получает превью текущего холста, изображения, прикреплённые к сообщению, и настоящий PNG от инструмента `render` (включая выбранный участок и координатную сетку). Включите **Assistant → ⚙ → Send document preview and attached images (vision model)**. Если флажок выключен, пиксели не передаются модели; импорт изображений и инструменты чтения цвета/контуров остаются доступны.

Для локальной модели выберите поддерживающий изображения GGUF и **соответствующий именно этой модели** файл в поле **Vision projector**. При автоматическом запуске он передаётся серверу как `--mmproj`; при ручном запуске добавьте этот параметр самостоятельно. Произвольный projector не превращает текстовую модель в vision-модель. Контракт описан в [официальной документации llama.cpp](https://github.com/ggml-org/llama.cpp/blob/master/docs/multimodal.md).

Нажмите **Test model and tools**: если сервер явно сообщает `modalities.vision: false`, Composa объясняет, что нужно загрузить модель/projector или выключить Vision. Старые серверы без этих метаданных проверяются обычным вызовом инструмента; это не подтверждает понимание изображений. Несуществующий файл projector обнаруживается до запуска процесса. Для API выберите модель с поддержкой изображений и вызова инструментов и включите тот же флажок; локальный mmproj не нужен. Приложение передаёт картинки в формате `image_url` через совместимый chat-completions API.

Файлы модели и projector не включены в релиз. Передача картинок покрыта автоматическими тестами; понимание изображения конкретной моделью требует проверки на ней.

## Другой компьютер

1. Установите Composa и совместимую llama.cpp. Выберите GGUF и runtime в настройках.
2. Нажмите Test model and tools, затем сохраните настройки.
3. При желании **Choose folder & create launcher** создаст командный файл запуска сервера. Пути к модели внутри выбранной папки будут относительными: такую папку можно перемещать вместе с её содержимым.

Для запуска из терминала поддерживаются `COMPOSA_LLAMA_SERVER`, `COMPOSA_LLAMA_MODEL`, `COMPOSA_LLAMA_URL`. Они имеют приоритет над сохранёнными настройками, чтобы перенесённая конфигурация не указывала на старый компьютер. Не сохраняйте чужие абсолютные пути в исходном коде. API-режим подключается к совместимому chat-completions endpoint без локального runtime.

## Папки, документы и скрипты

В **Read folders → Add folder** добавьте папки с изображениями, текстовыми заданиями или данными. Агент получает список, читает текст частями и импортирует изображения. Удаление строки немедленно отзывает доступ. Доступ только для чтения, без перехода по ссылкам/junction; содержимое файлов считается данными, а не командами агенту. Этот же доступ используют MCP и скрипты Composa.

Агент может открыть изображение или `.cmps` даже из пустого приложения. Сначала выбирается документ, затем выполняется одна транзакция правок. Переключать документы после начала правок нельзя. Открытая вкладка остаётся открытой при ошибке, но неуспешные правки откатываются. PSD/RAW по-прежнему открываются через диалог File menu.

В чате доступны режимы:

- **Auto** — выполнить запрос, проверить результат; изменения документа отменяются одним Undo.
- **Composa script** — выдать код для сохранения, библиотеки скриптов или явного запуска.
- **Photoshop script (.jsx)** — выдать ExtendScript для Photoshop; сохраните `.jsx` и запустите Photoshop → File → Scripts → Browse. Composa не исполняет JSX и не притворяется подключённым Photoshop.

Скрипты имеют ограниченные время, память и число инструкций. `doc` — готовый короткий доступ к `app.activeDocument`; явное `const doc = app.activeDocument` также допустимо. Скрипты могут использовать `files.roots()`, `files.list(path)`, `await files.readText(path)` и `doc.addImageFile(path)` в разрешённых папках. У них нет произвольного доступа к процессам, сети или .NET. MCP предоставляет `get_script_api` и `execute_script`; исключение скрипта откатывает изменения целиком.

Перед выдачей артефакта проверяется синтаксис; для Photoshop — ES3 и известные ошибки создания DOM-объектов. Агент получает до двух попыток исправления. Это статическая проверка без исполнения, она не заменяет запуск JSX в вашей версии Photoshop и не подтверждает правильность всех вызовов его API.

## Проверки

`dotnet test` запускает детерминированные проверки, включая настоящий stdio MCP bridge, откат/Undo/Redo, поиск инструментов, чтение файлов, защиту границ папок, выдачу JSX и headless-снимки интерфейса.

Полная проверка с моделью (PowerShell 7 также работает на Linux):

```powershell
./scripts/test-agent.ps1 -Server '/path/to/llama-server' -Model '/path/to/model.gguf'
```

Для повторения одного редакторского сценария добавьте `-Cases mask` или `-Cases 'batch,smart-object'`. Без Cases проверяются все шесть задач и отдельный сценарий «папка → изображение → JSON-разметка → редактирование → повторно используемый Composa-скрипт → Photoshop JSX». Без переменных live-проверки отмечаются пропущенными, а не успешными.

Оценка проверяет реальные свойства и пиксели документа, а также Undo/Redo; рассказ модели не засчитывается как выполнение. Созданный Composa-код исполняется на отдельном документе. Photoshop JSX проверяется на DOM-фикстуре; для подтверждения совместимости конкретной версии Photoshop нужен запуск в ней. JSON-отчёты и журнал находятся в `tests/Composa.App.Tests/bin/Release/net10.0/artifacts/assistant-evals`, снимки — в `artifacts/screenshots`.
