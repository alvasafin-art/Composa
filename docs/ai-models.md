# Модели и подключение ComfyUI

Composa не загружает веса генеративных моделей самостоятельно. Их загружает сервер ComfyUI. Клиент получает точные доступные имена от узлов сервера через `/object_info`, включая подпапки и дополнительные хранилища, зарегистрированные в ComfyUI.

## Настройка

1. Запустите ComfyUI и убедитесь, что его страница открывается в браузере.
2. В Composa откройте **AI → ComfyUI Settings** и укажите полный адрес сервера.
3. Нажмите **Refresh Models / Test Connection**. В разделе **Models on ComfyUI** появятся списки файлов для загрузчиков выбранного workflow pack: основная модель, текстовый энкодер, VAE, апскейлер и выделение объекта.
4. Выберите нужные файлы и нажмите **OK**. Настройки сохраняются отдельно для каждого адреса сервера и workflow; **Cancel** не применяет изменения выбора моделей.

**Workflow default** сохраняет заданное workflow имя. Если этот файл находится в единственной подпапке на сервере, Composa использует полное имя из серверного списка. Если одно имя найдено в нескольких подпапках, требуется явный выбор. Пропавшая явно выбранная подпапка не заменяется другой автоматически.

Модель в списке загрузчика не обязательно подходит всем workflow. Например, SDXL не становится совместимым с FLUX.2 от выбора в списке UNETLoader. Основная модель, энкодер и VAE должны соответствовать архитектуре workflow и поддержке установленного ComfyUI.

Перед отправкой исходных картинок Composa проверяет узлы и модели конкретной операции. Отсутствие генеративной модели не мешает отдельному workflow апскейла. После установки новых файлов или узлов обновите списки; при необходимости перезапустите ComfyUI.

## Один компьютер и локальная сеть

- На одном компьютере обычно используется `http://127.0.0.1:8188`.
- На другом компьютере нужен адрес машины с ComfyUI, например `http://192.168.1.50:8188`. `127.0.0.1` всегда означает текущий компьютер, а не соседний.
- ComfyUI должен слушать интерфейс локальной сети, и его порт должен быть разрешён в брандмауэре сервера. Не открывайте его в интернет для этой задачи.
- Копировать веса на компьютер с Composa или подключать сетевой диск не требуется. Исходные изображения отправляются по HTTP, результат скачивается с сервера.

Папки `models`, `shared` и произвольные дополнительные каталоги настраиваются **на стороне ComfyUI**. Для portable/manual установок используется `extra_model_paths.yaml`; ComfyUI Desktop имеет собственные настройки хранилищ. Просто указать папку на клиенте недостаточно: сервер должен знать её и иметь к ней доступ. См. [официальные настройки дополнительных путей](https://docs.comfy.org/basic-concepts/models#adding-extra-model-paths).

## Если список пуст или модель не найдена

- **Нет подключения:** проверьте, запущен ли ComfyUI и открывается ли его адрес с компьютера с Composa.
- **Missing node:** установите нужный custom node в ComfyUI и его зависимости, затем перезапустите сервер.
- **Not found or ambiguous:** выберите полный идентификатор файла из списка. Composa не выбирает другую модель наугад.
- **Loader does not report a model list:** установленный узел не предоставил список через API. Проверьте узел и его настройки в самом ComfyUI.
- Если файлы отсутствуют и в выпадающем списке соответствующего узла в браузере ComfyUI, исправлять нужно его пути к моделям.

## Чат-ассистент — отдельное подключение

GGUF-модель ассистента не относится к этим спискам ComfyUI. В **Assistant Settings** можно указать локальный файл GGUF и исполняемый файл llama.cpp через **Browse…**, либо использовать уже запущенный сервер или API-провайдера. Удалённому ассистенту локальный путь к весам не нужен; автоматически запускать llama.cpp разрешено только на текущем компьютере.

## Операции, варианты и видеопамять

- **AI → ComfyUI Settings** — подключение и выбор моделей. **AI → AI Advanced** или **Advanced…** на плавающей панели — мегапиксели, размер референсов, seed, mask context/grow/blend и режим вариантов.
- **Variants: 1 / 3** задаёт число результатов. **List** (по умолчанию) последовательно выполняет генерации с разными seed, повторно используя загруженные картинки. **Batch** обрабатывает три варианта вместе и требует больше VRAM. Нестандартный workflow без поддерживаемого latent batch нужно запускать в List; программа сообщает об этом до отправки изображений.
- Варианты появляются в общей группе: виден только первый. Кнопки **1, 2, 3** в верхней строке переключают результат; исходное изображение остаётся нетронутым. Одна отмена возвращает состояние до всей генерации. Ошибка/отмена до вставки результатов не оставляет частично созданных слоёв.
- **Upscale…** предлагает только **×2 / ×4**. Без выделения изменяется размер изображения и холста. С выделением результат помещается в исходную область через её маску, холст не увеличивается.
- Штатный узел ComfyUI апскейлит плитками. Масштаб внутри модели задан весами: модель ×4 всё равно вычисляет ×4, даже если конечный результат ×2. Composa не уменьшает исходник перед моделью; итоговый размер задаётся до сохранения/скачивания результата. Для минимального расхода памяти при ×2 выбирайте настоящую модель ×2. Поддержка файла зависит от загрузчика ComfyUI/Spandrel, а не только от расширения.

## Смарт-объекты

**Layer → Convert to Smart Object** сохраняет редактируемые слои внутри проекта `.cmps`. Двойной щелчок по миниатюре или **Edit Smart Object Contents…** открывает содержимое во вкладке. Правьте слои и нажмите **Ctrl+S / Save contents** — обновятся связанные экземпляры в родительском документе, сохранив наружную трансформацию, маску и эффекты. После этого сохраните сам родительский проект.

Обычная копия использует общий источник. **New Smart Object via Copy** создаёт независимый. **Rasterize Layer** отключает редактируемый источник, сохраняя изображение; отмена возвращает смарт-объект. Вложенное содержимое и общий источник сохраняются внутри одного проекта, внешние файлы не требуются. Это собственные встроенные объекты Composa, не полноценный импорт Photoshop Smart Objects или связанные внешние файлы. Новые проекты имеют формат 7: для их открытия нужна эта или более новая сборка; старые проекты продолжают открываться.
